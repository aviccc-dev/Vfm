## 1. העיקרון
- גיבוי בנוי רק מפעולות רגילות של מנהל הקבצים, בלי מנגנון גיבוי נפרד.
- ביעד: `נוכחי` = מראה מדויקת; `היסטוריה/<NNNN dd.MM.yyyy HH-mm-ss>` = מה שיצא מ`נוכחי` בכל גיבוי.
- מצב בזמן T = גרסאות ש"נוסף" שלהן ≤ T ושלא יצאו עד T. פירוש השינוי (נערך/הועבר/הועתק/נמחק/חדש) נגזר מהשוואה ואינו נשמר.

## 2. הפונקציות להוספה ל-vfm (כולן בפקודות ובתנאים, בלי מסך חדש)
1. **השוואה לפי מסלול** (וגם תיקיות, כולל ריקות): רכיב רביעי ב-`DupMode`, רק בהגדרת `השוואה` ובפקודה. מסך הכפולים לא משתנה.
2. **העתקה והעברה עם שמירת מסלול:** שורש מקור ושורש יעד; קריאה אחת ל-`Physical.transfer` לכל תיקיית יעד. בגיבוי, שם תפוס = כישלון ודיווח, בלי שאלה.
3. **"נוסף" עובר בהעברה** לפי מקור→יעד מדויקים (`moved`). הניחוש לפי גודל+תאריך רק לשינויים מחוץ לתוכנה. (פער ידוע: שני קבצים באותו גודל ותאריך באותו גיבוי.)
4. **שדה `full` באינדקס** (8 בתים מ-SHA-256, נמחק כשגודל או תאריך משתנים, גרסת אינדקס חדשה). השימוש בו **אופציה**: ברירת מחדל מדגמית/משפך; אופציה "מלאה ואיטית". הוספת האופציה בסוף.
5. **תנאי חיפוש `מצב בתאריך:"…"`**, באופי הרשימה החכמה.

3. **קובץ חלקי בשם הסופי.** `copyFile` כותב ישר לשם הסופי; אם הכרטיס נשלף או המכשיר כבה באמצע, נשאר קובץ שבור בנוכחי, ובגיבוי הבא הוא "גרסה ישנה" שעוברת להיסטוריה. **הצעה:** כתיבה לשם זמני ושינוי שם בסוף (הדפוס כבר קיים בקוד לאינדקס ולהגדרות); ההשוואה מתעלמת מקבצים זמניים ומנקה אותם.

6. **היעד בחיפוש הרגיל.** אם היעד באינדקס כמו כל תיקייה, כל חיפוש רגיל יחזיר גם את העותק בנוכחי וכל גרסה בהיסטוריה, ומסך הכפולים יראה הכול ככפול. **הצעה:** תיקיות שיש בהן תג גיבוי מוחרגות מחיפוש ומרשימות רגילים, ונכללות רק בחיפוש מפורש בגיבוי (שחזור, `מצב בתאריך`).
